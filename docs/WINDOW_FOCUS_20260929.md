# Computer Use 后 AE 只剩标题栏：根因、修复与实机记录

当前结论：本机坏还原矩形已修正，跨重启验收通过；激活可能解除最大化这一工具行为仍存在。最新证据见文末“第三轮”。前两轮为定位过程。

2026-09-29，Windows / After Effects Beta 27.0x58 / Computer Use 26.924.22138。

主人报告并提供截图后，已通过当前实例复现。先把 AE 恢复最大化，然后分别比较：

| 操作 | 观察结果（截图逻辑尺寸） |
| --- | --- |
| 只读 get_window_state | 1707×912 保持正常 |
| activate_window | 1707×912 保持正常 |
| 最大化窗口先最小化、再 activate_window | 恢复 1707×912 |

| 关闭首选项 | 主窗口仍为 146×30 |

| 点击首选项“取消” | 主窗口仍为 1707×912 |

已验证的处理方式：首选项操作改走菜单，关闭弹窗用可见按钮；必要时通过当前观察到的“最大化”按钮恢复主窗口。截图、激活和正常最小化恢复在第一轮样本中没有触发问题；后续反例见下文。

第一轮只观察到模拟组合键这一条触发路径，尚未确定是输入注入、AE 本身还是第三方插件组合的底层问题。三个当前运行的个人 AutoHotkey 脚本中未发现该组合键或窗口缩放绑定。没有修改官方 Computer Use 包，也没有新增强制最大化的常驻程序。此项作为已验证规避记录，不计入 17 类 AE2Claude 源码修复。

本轮之后在此任务中停止使用该快捷键，最终保留 AE 最大化的工作界面。


## 第二轮 Beta 验收补充：激活窗口也有反例

同日第二轮没有使用上述组合键，但在 Beta 被 Chrome 遮挡后调用 `activate_window`，再次观察到主窗口为 146×30；点击当时截图中的最大化按钮恢复 1707×912。正常关闭最大化的 Beta 后重新启动，首次只读截图也曾保持正常 1707×912。

因此不能将问题限定为组合键，也不能声称 Computer Use 激活已经彻底修复。当前只能确认可恢复的操作方式；AE、第三方窗口插件和输入/激活实现之间的责任尚未分离。后续根因排查应使用同一空白工程，分别记录激活前后的窗口状态，并在独立、可回退的环境做组件对照，不能靠常驻强制最大化掩盖。

本轮没有修改官方 Computer Use 代码或用户工作区布局配置。此问题不属于本轮 AE2Claude 批处理源码修复的完成项。


## 第三轮根因对照与配置修复

同日继续追查，已定位并修正本机“激活后只剩标题栏”的直接原因：标准工作区将主窗口的还原矩形持久化成了异常小的区域，而 Computer Use 从后台激活窗口时会触发还原。

### 区分原因的实机证据

1. 激活前最大化窗口为 1707×912，激活后为 146×30。
2. 恢复最大化后，直接点击 AE 标题栏的“还原”也得到 146×30；因此无需特定快捷键或脚本请求就能复现。
3. 当前工作区偏好 `Current Workspace3=E6A087E58786` 解码为“标准”。其工作副本与原始副本 `UserWorkspace_4.xml` 都保存了 `TopLevelFrame-0 → WinState → NormalPos = [0,0,353,79]`。这是物理坐标中的外框矩形；截图尺寸是排除边界、经过缩放的逻辑尺寸，两者不是同一单位。
4. 在空白工程中正常退出 Beta，备份两个文件，只改上述矩形，再用完全相同的还原/激活动作测试，窗口保持正常。原插件组合未被停用。

当前定位到的是“坏还原矩形 + 激活触发还原”的可复现因果链。最初是哪次操作写入坏矩形仍无证据，不将其归咎于某个第三方插件或 AE2Claude。

### 实际修复

修改位置均在 `%APPDATA%/Adobe/After Effects (Beta)/27.0/`：

- `修改后的工作区/UserWorkspace_4.xml`
- `原始用户工作区/UserWorkspace_4.xml`

仅将主窗口的 `NormalPos` 改为 `[120,80,3480,1940]`，即 3360×1860 的物理外框，保持 `ShowCmd=3`。本机对应的可见普通窗口为 1483×821，最大化为 1707×912。其他面板 XML 在补丁阶段保持字节不变；后续 AE 正常保存时可能自行重排其序列化内容。

同时修复原始工作区副本，是为了避免以后重置该工作区又加载 353×79。修改前已保存原文件和哈希；修复前的尺寸实验曾移动并横向扩大普通窗口，因此实际停机时工作副本矩形变为 `[3476,974,3854,1053]`，仍只有 79 像素高。备份与 `repair.json` 保留了这一变化，没有将两个不同时间点混为一谈。

没有重置全部首选项，没有禁用窗口/效果插件，没有更换 AEX，也没有加入强制最大化后台程序或修改官方 Computer Use 包。

### 剩余边界

“缩成标题栏”在上述路径已消除。Computer Use 的 `activate_window` 和 `Raise` 仍可能把最大化改成普通窗口，这是另一项仍存在的工具行为；本轮没有修改其官方实现。需要最大化时，在新截图中双击标题栏即可，不依据激活前的坐标直接点击。

收尾尝试恢复用于对照的浏览器窗口时，Computer Use 因无法可靠判定当前浏览器 URL 而终止本轮 UI 操作。未绕过该限制。Beta 最后一次截图为正常的 1483×821 普通窗口，不能声称最后又恢复了最大化。

原始证据和可恢复备份位于本次对话的 `work/beta-window-root/`，用户交付证据包包含相应文件。回退前必须关闭 AE；若此后改过布局，不应直接覆盖完整旧工作区，而应只处理对应的主窗口矩形。
